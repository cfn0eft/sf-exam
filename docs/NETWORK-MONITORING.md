# 接続元・端末情報

管理者ビューの「🔐 接続元・端末」タブに、承認済みアカウントの接続元と端末情報をまとめて表示する。
目的は不正利用の確認とアカウント管理であり、接続判定だけを理由に自動停止しない。

## 取得・保存する情報

- 末尾を伏せたIP（IPv4は `203.0.113.xxx`、IPv6は先頭4ブロックまで）
- 接続元の国・地域・都市、回線組織、ASN
- 登録企業回線／企業VPN・セキュアゲートウェイ候補／クラウド回線候補の参考判定
- ブラウザ、OS、言語、タイムゾーン、画面サイズ
- アカウントとブラウザの組み合わせごとに `localStorage` へ生成したランダムな端末ID
- 端末ごとの初回・最終アクセス、記録回数、直近の接続履歴

生のIPはブラウザ上で企業IP帯との照合にだけ使い、Firestoreへ保存しない。
接続元IPと国は Cloudflare の公開 trace、回線組織・ASN・地域は ipwho.is からベストエフォートで取得する。
どちらかが失敗してもログインと学習は妨げない。

通常は Firestore の `netDevices` / `netAccess` / `netUpdated` に保存する。Firebase側が旧ルールでこれらを拒否した場合は、既存ルールでも書き込める予約領域 `stores.__sfq_network__` へ自動的に切り替える。管理者ビューは両方を比較し、新しい方を表示する。

## 会社VPNの登録

`firebase-config.js` の `window.SFQ_NETWORK_MONITORING.corporateNetworks` に追加する。

```js
corporateNetworks: [
  {
    name: "○○株式会社",
    cidrs: ["203.0.113.0/24", "198.51.100.42"],
    orgPatterns: ["Example Corporation", "Example Zscaler"]
  }
]
```

- `cidrs`: 会社から提供されたVPN出口のIPv4 CIDRまたはIP。これとの一致は「高」信頼度。
- `orgPatterns`: ipwho.is が返す回線組織名に対する正規表現。これとの一致は「中」信頼度。
- IPv6は現在、完全一致だけに対応する。IPv6 CIDRは判定しない。
- 設定内容は静的ファイルとして公開される。秘密情報や社内専用の説明は書かない。

## 管理者ビュー

- 「🔐 接続元・端末」タブに最新の回線判定を表示する。
- 「接続確認」「登録企業回線」「VPN/クラウド候補」で絞り込める。
- 同タブの「接続詳細」に端末一覧、マスク済みIP、回線組織、地域、直近30日の接続履歴を表示する。
- 2台以上が同時にオンライン、または10分以内に別端末・別回線へ切り替わった場合は注意表示する。
- CSV書き出しにも最新の接続情報と注意理由を含める。

## 保存期間と削除

`retainDays` の既定値は30日。本人が次にアクセスした時と管理者ビューを開いた時に、期限切れの端末・接続履歴を削除する。
アカウントを完全削除すると接続情報も同じ `progress/{uid}` ドキュメントとともに削除される。

## セキュリティ上の限界

このサイトは静的なクライアントアプリなので、利用者本人がFirestoreへ保存する接続情報は監査証跡ではない。
ブラウザ情報は変更でき、記録処理を止めることもできる。IP・VPN判定も携帯回線、共有回線、VPN、スプリットトンネルで変化する。
したがって参考表示として使用し、それだけで本人性・不正利用・アカウント共有を断定しない。

改ざん耐性が必要な場合は、Firebase Callable Functionsなどサーバー側でFirebase IDトークンを検証し、接続元IPと端末情報を管理者専用フィールドへ記録する構成へ移行する。

## Firestoreルール

`firestore.rules` に `netDevices` / `netAccess` / `netUpdated` が本人書込可能フィールドとして追加されている。
既存Firebaseプロジェクトでは、ルートの `firestore.rules` をFirebaseコンソールへ貼り直して公開することを推奨する。未反映でも互換保存へ自動的に切り替わるため、接続情報の記録は継続できる。
