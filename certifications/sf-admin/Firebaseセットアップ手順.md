# Firebase セットアップ手順（アカウント別・端末間 進捗同期）

この手順を一度だけ行えば、学習サイトに **ID＋パスワードのログイン** がつき、進捗が **クラウド（Firebase）** に保存されます。
同じID/パスワードでログインすれば、**PC・スマホ・別ブラウザ** のどこでも同じ進捗の続きから学習でき、**アカウントごとに進捗が完全に分かれます**。

所要時間は約10分。費用は無料枠の範囲で十分です（クレジットカード登録も不要）。

---

## できるようになること

- 「新規登録」で自分のIDを作成 → そのアカウントだけの進捗が記録される
- 別の端末で同じID/パスワードでログイン → 進捗がそのまま引き継がれる
- 複数人が同じサイトを使っても、各自のIDで進捗が分かれる
- ログアウトすれば、その端末には進捗データが残らない（次の人に見えない）

---

## ステップ 1: Firebase プロジェクトを作る

1. ブラウザで <https://console.firebase.google.com/> を開き、Googleアカウントでログインします。
2. 「**プロジェクトを追加**」をクリック。
3. プロジェクト名（例: `sf-quiz`）を入力して「続行」。
4. 「Google アナリティクス」は **オフ（無効）でOK**。そのまま「プロジェクトを作成」。
5. 完了したら「続行」。

## ステップ 2: ウェブアプリを登録して設定キーを取得する

1. プロジェクトのトップ画面で、`</>`（ウェブ）のアイコンをクリック。
2. アプリのニックネーム（例: `quiz-web`）を入力。「Firebase Hosting」は **チェック不要**。「アプリを登録」。
3. 次の画面に表示される `firebaseConfig` の中身（下のような形）をコピーします。

   ```js
   const firebaseConfig = {
     apiKey: "AIzaSy........",
     authDomain: "sf-quiz-xxxx.firebaseapp.com",
     projectId: "sf-quiz-xxxx",
     storageBucket: "sf-quiz-xxxx.appspot.com",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef......"
   };
   ```

4. プロジェクト内の **`firebase-config.js`** をテキストエディタで開き、`"ここに〜を貼り付け"` の部分を、コピーした値に置き換えます。
   - `apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId` の6つを、それぞれ対応する箇所に貼り付け。
   - ダブルクォート `" "` の中に入れること。末尾のカンマ `,` は消さない。
   - 編集するのは **この1ファイルだけ** です（PC版・モバイル版の両方がこれを読み込みます）。

## ステップ 3: ログイン方法（メール/パスワード）を有効にする

1. 左メニュー「**構築 → Authentication**」を開き、「**始める**」をクリック。
2. 「Sign-in method（ログイン方法）」タブで「**メール/パスワード**」を選択。
3. 1つ目のスイッチ（メール/パスワード）を **オン** にして「保存」。
   - ※「メールリンク」は不要なので、そのままでOK。

> このサイトは「ID」を内部で `ID@sfquiz.local` というメール形式に変換して、この仕組みを使っています。Googleアカウント等は不要で、好きなID＋パスワードで登録できます。

## ステップ 4: データベース（Firestore）を作る

1. 左メニュー「**構築 → Firestore Database**」を開き、「**データベースの作成**」をクリック。
2. ロケーションは `asia-northeast1`（東京）など近い場所を選択。
3. モードは一旦どちらでもOK（次のステップでルールを設定します）。「有効にする / 作成」。

## ステップ 5: セキュリティルールを設定する（重要）

各ユーザーは **自分の進捗だけ** 読み書きでき、**管理者（admin）だけは全員分を閲覧・管理** できるようにします。

1. Firestore の「**ルール**」タブを開く。
2. 内容を **すべて下記に置き換え**、「**公開（Publish）**」をクリック。

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {

       // 管理者の判定（このメールでログインした人を管理者とみなす）
       function isAdmin() {
         return request.auth != null &&
           request.auth.token.email in [
             "admin@sfquiz.local"
           ];
       }

       match /progress/{uid} {
         // 読み取り: 本人 または 管理者
         allow read:  if request.auth != null && (request.auth.uid == uid || isAdmin());

         // 書き込み: 管理者は全権。本人は「自分の access を承認に書き換えられない」制約付きで許可。
         //  → access（利用承認フラグ）を付与/停止できるのは管理者だけ。本人は進捗や
         //     フィードバックを保存できるが、access は据え置き or 自分で 'pending' にするだけ可。
         allow write: if request.auth != null && (
             isAdmin() ||
             (request.auth.uid == uid && (
                 !('access' in request.resource.data) ||                                   // access を含めない通常保存
                 request.resource.data.access == 'pending' ||                              // 自分で承認待ちにするのは可
                 (resource != null && request.resource.data.access == resource.data.access) // 既存の access を維持
             ))
         );
       }

       // 一斉お知らせ（管理者→全利用者）。全ログインユーザーが読め、書けるのは管理者だけ。
       // ※ 個別お知らせ・チャットは各自の progress/{uid} 内（notices[]/chat[]）に入るため、
       //   上の progress ルールだけで動作し、ここは「一斉お知らせ」専用。
       match /broadcast/{doc} {
         allow read:  if request.auth != null;
         allow write: if isAdmin();
       }
     }
   }
   ```

   - これで、本人以外は他人の進捗を読めません。**管理者（`admin@sfquiz.local`）だけは全員分を閲覧・リセット・削除でき、利用承認（access）の付与/停止もできます。**
   - **重要（アクセス承認制）**: `access` フィールドは **管理者しか `'approved'` にできません**。一般ユーザーは自分で承認状態を書き換えられないため、ここを上記ルールにしないと「誰でも自分を承認」できてしまい無意味になります。新規登録者は既定で `'pending'`（承認待ち＝全面ロック）になり、管理者ビューの「✅ 承認」を押すと利用できるようになります。
   - 管理者IDを `admin` 以外にしたい／複数にしたい場合は、上の `"admin@sfquiz.local"` の行をそのIDのメール（例 `"daiki@sfquiz.local"`）に変更（カンマ区切りで複数可）し、**`firebase-config.js` の `SFQ_ADMIN_IDS` も同じIDに合わせて**ください。

## ステップ 6: GitHub Pages に反映する

編集した `firebase-config.js` と、新しく追加された `cloud-sync.js` を含めて、リポジトリに反映します。

- GitHub Desktop やコマンドで、`firebase-config.js`・`cloud-sync.js`・`quiz.html`・`mobile/index.html` を **commit → push**。
- 数十秒後、GitHub Pages のサイトを開くと、ログイン画面が表示されます。

> push するファイル: `firebase-config.js`, `cloud-sync.js`, `quiz.html`, `mobile/index.html`（4つとも同じフォルダ構成のまま）

---

## 使い方

- **初めて**: ID（半角英数字、例 `daiki`）とパスワード（6文字以上）を入れて「**新規登録**」。
  - このサイトで初めて作るアカウントには、その端末にすでにある学習進捗が自動で引き継がれます。
- **2回目以降**: 同じID/パスワードで「**ログイン**」。
- **別の端末で続ける**: その端末でサイトを開き、同じID/パスワードでログイン → 進捗が同期されます。
- **ログアウト**: 画面右上のバッジの「ログアウト」ボタン。その端末からは進捗データが消えます（クラウドには残っています）。
- 右上のバッジに「保存済み」と出れば、クラウド保存が完了しています。

---

## 管理者として全アカウントを見る

1. ID `admin`（＝`firebase-config.js` の `SFQ_ADMIN_IDS` に設定したID）とパスワードで、初回は「**新規登録**」してアカウントを作成します。
2. 以降、その `admin` でログインすると、画面右上に **「👑 管理者」ボタン** が表示されます。
3. ボタンを押すと **管理者ビュー** が開き、全アカウントの一覧が見られます。
   - 各アカウントの **回答した問題数・正答率・正解／不正解数・連続正解・ブックマーク数・単語学習数・最終更新日時** が一覧表示されます。
   - 「**詳細**」を押すと、そのアカウントの **問題ごとの正解／不正解／正答率** の表が開きます。
   - 「**リセット**」でそのアカウントの進捗を初期化、「**削除**」で進捗データを削除できます。
   - 「**CSV書き出し**」で全アカウントの成績を表計算ソフト用に保存できます（Excel対応のUTF-8）。
4. 管理者機能が表示されない／一覧の読み込みに失敗する場合は、ステップ5のルールの管理者メールと、`firebase-config.js` の `SFQ_ADMIN_IDS` が一致しているか確認してください。

> 「削除」は **進捗データ** を消すものです。ログインアカウント自体（ID/パスワード）を完全に消すには、Firebaseコンソールの **Authentication → ユーザー** から該当ユーザーを削除してください。

---

## 注意点

- **同時編集**: 同じアカウントで2台同時に学習すると、後から保存した方の内容で上書きされます（通常の使い方では問題ありません）。
- **パスワードを忘れた場合**: この簡易方式にはパスワード再発行機能がありません。Firebase コンソールの Authentication 画面から該当ユーザーを削除し、新規登録し直してください（その場合、そのアカウントの進捗はリセットされます）。
- **セキュリティ**: 仲間内での利用を想定した簡易ログインです。パスワードはFirebaseが安全に管理しますが、IDは推測されやすいので、機密情報は保存しないでください。
- **無料枠**: Firebase の無料プラン（Sparkプラン）で十分動作します。進捗保存は0.8秒ごとにまとめて1回書き込む設計なので、無料枠の上限にはほぼ達しません。

---

## うまくいかないとき

- **ログイン画面に「設定がまだ完了していません」と出る** → `firebase-config.js` の貼り付け漏れ。6項目すべてが `"ここに〜"` のままでないか確認。
- **「メール/パスワードログインが有効になっていません」と出る** → ステップ3が未完了。
- **保存されない／「オフライン」と出続ける** → ステップ4・5（Firestore作成とルール公開）が未完了か、ネット未接続。
- **何も起きない** → ブラウザのキャッシュが原因のことがあります。スーパーリロード（Ctrl/Cmd+Shift+R）を試してください。
