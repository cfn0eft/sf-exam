# Q96. Cloud Kicks社には靴という名前のカスタムオブジェクトがあります。管理者…

**URL:** https://tysonblog-whitelabel.com/salesforce-admin-practice96

## 問題

Cloud Kicks社には靴という名前のカスタムオブジェクトがあります。管理者は、取引先と靴の間にリレーションシップが作成されたときに、靴のレコードが孤立しないようにすることを求められています。この要件を満たすために、管理者は何をすべきでしょうか。

## 選択肢

- 間接参照関係を作成する。
- カスタム暗号化項目を作成する。
- 取引先階層を作成する。
- 主従関係を作成する。

## 正解

> **主従関係を作成する。**

## 解説

それぞれの選択肢の理由について説明します。

□ 間接参照関係を作成する。これは不正解です。間接参照関係は、外部オブジェクトを親の標準またはカスタムオブジェクトに結び付けるために使用され、通常、Salesforce外のデータを参照するために使用されます。このシナリオでは、取引先と靴の間のリレーションシップを作成するためには適していません。

□ カスタム暗号化項目を作成する。これは不正解です。カスタム項目のデータ型である[テキスト (暗号化)]は、データのセキュリティとプライバシーを強化するために使用されますが、リレーションシップの管理やレコードが孤立するのを防ぐための機能は提供しません。取引先と靴の間のリレーションシップを保つためには適していません。

□ 取引先階層を作成する。これは不正解です。取引先階層は、取引先レコード間での階層的な関係を構築するもので、主に親会社と子会社の関係を表します。靴というカスタムオブジェクトとの直接的な関連付けには使用されません。

□ 主従関係を作成する。これは正解です。主従関係は、親オブジェクト(取引先)と子オブジェクト(靴)との間に強いリンクを作成します。この関係では、親レコードが削除されると、関連する子レコードも自動的に削除されます。これにより、靴のレコードが孤立することを防ぎ、このシナリオの要件を満たします。

参考：オブジェクトリレーションの概要
