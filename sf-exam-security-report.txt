1. アクセスした人のどんな情報を取得しているか
================================================================

【クラウド同期（アカウント登録）した場合】

Firebase Auth + Firestore に以下が保存されます。

  項目                   内容                          備考
  UID                   Firebase 自動生成の識別子       個人特定不可な内部ID
  メール（内部）          {登録ID}@sfquiz.local の形式   実際のメールアドレスは取得しない
  名前                   利用申請フォームで入力したもの   任意・承認申請時のみ
  アクセス状態            pending / approved / blocked   管理者のみ変更可
  学習進捗               下表参照                        資格ごとに保存
  フィードバック          不具合報告の内容                ユーザーが送信した場合のみ
  更新日時               最終同期のタイムスタンプ         自動生成

学習進捗データの詳細（クラウド同期される内容）:
  - 正解・不正解の履歴（問題IDごと）
  - ブックマーク一覧
  - 模試の得点履歴（最新50件）
  - 間隔反復（SRS）スケジュール
  - 日別の解答数
  - 自分のメモ・フェインマン要約
  - 経験値・バッジ・ウィークリーミッション状態
  - 合格確度の日次推移
  - 学習時間（合計・分野別・時間帯別）


【ローカルストレージ（クラウド非同期）】

ブラウザのデータを消すまで端末内に残るだけで、サーバーには送信されません。

  キー                    内容
  学習進捗データ           上記と同じ（オフラインバックアップ）
  中断した模試の状態        再開用
  フォントサイズ設定        UI設定
  ダークモード設定          UI設定
  ニュース既読状態          バナー制御用

2. 接続端末からどんな情報を抜いているか
================================================================

結論: ほぼ何も取得していません。


【取得する情報（不具合報告を送ったときのみ）】

不具合報告（フィードバック）をユーザーが送信したときだけ、
以下が Firestore に保存されます。

  項目                          例                           目的
  User-Agent 文字列（300文字）   Chrome/125 Windows NT 10.0   ブラウザ・OS環境の把握
  現在のページURL（300文字）     ../sf-admin/index.html        どのページで発生したか
  アプリバージョン               v=106                         キャッシュバージョン確認
  報告内容・カテゴリ             テキスト（2000文字以内）       問題の修正対応
  タイムスタンプ                 Unix時刻                      報告日時


【取得しない情報】

  IPアドレス              → 取得しない
                            （Firebase が内部でログする可能性はあるが、このアプリは取得しない）
  画面サイズ・解像度       → 取得しない
  GPS・位置情報           → 取得しない
  カメラ・マイク           → 使用しない
  Cookie                 → 使用しない（localStorage のみ使用）
  インストール済みアプリ    → 取得しない
  閲覧履歴                → 取得しない
  キー入力ログ             → 取得しない
  Google Analytics        → 設定はあるが一切使用していない（初期化コードが存在しない）

4. セキュリティ上の状況
================================================================

【安全な点】

  項目                   状況
  データの分離            Firestore ルールで「本人しか自分のデータを読み書きできない」を強制
  承認制アクセス          管理者が承認するまでロック画面。ユーザー自身は approved に昇格できない
  API キーの制限          Google Cloud Console でリファラー制限済み
                          （cfn0eft.github.io と localhost のみ有効）
  パスワード管理          Firebase が内部でハッシュ化。アプリ側にはパスワード本文が届かない
  追跡・広告なし          アナリティクス・サードパーティ広告・クロスサイトトラッキングは一切なし


【Firebase APIキーがソースコードに公開されている件について】

  これは意図的かつ安全です。
  Firebase の Web SDK の設計として、APIキーはブラウザに公開される前提で
  作られており、実際のアクセス制御は Firestore のセキュリティルールが行います。
  GitHub のシークレットスキャン警告は誤検知（false positive）です。


【注意すべきリスク】

  リスク                      内容                                   深刻度
  管理者アカウント侵害          admin アカウントが乗っ取られると           中
                              全ユーザーデータを閲覧・削除可能
  Firestore ルールの誤設定     ルールを誤って変更すると全データ公開        高（現状は問題なし）
  自己スコア改ざん             技術的に自分の正答数を書き換え可能          低（他人には影響なし）
  Firestore 読み書きの濫用     レート制限がないため無料枠を消費される可能性  低
  フィードバック内の情報        報告者のブラウザ情報が管理者に見える         低（報告した場合のみ）


【「他人のデータを盗める？」への回答】

  → できません。

  Firestore のルール（request.auth.uid == uid）により、
  他のユーザーのデータを読み書きするリクエストは Firebase が 403 で拒否します。

  問題データ（questions.json）は GitHub Pages で公開されている静的ファイルなので
  誰でも閲覧できますが、これは学習サイトとして想定内の公開情報です。

5. まとめ
================================================================

  観点                   評価
  プライバシーリスク       低（最小限の収集・追跡なし）
  セキュリティリスク       低（Firestore ルールによる分離が機能中）
  データの透明性          高（出典明記・オープンソース）

このサイトは学習データ以外の個人情報を収集せず、
アナリティクスや広告追跡も行っていません。

主なリスクは管理者アカウントの管理と
Firestore ルールの適切な維持にあります。
